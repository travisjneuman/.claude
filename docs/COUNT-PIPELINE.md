# Public count pipeline

`scripts/generate-counts.mjs` is the single producer. `scripts/count-inventory.mjs` owns source definitions shared with index generation. `counts.json` owns the public identity lists consumed by website collectors. No new services, workflows, schedules, dependencies, or remote requests are involved.

## Populations

- **Skills:** public real toolkit `skills/**/SKILL.md` files, not an authored-only or body-deduplicated unique-skill count. Neither linked directories nor linked files count (including linked vendor skills). Gitignore and explicit hidden, private/local, synced, vendor/vendored/vendor-skills, imported/installed/plugin-cache, backup, test/example, draft/archive, template and other directory exclusions apply together. Private/vendor/installed availability across harnesses is a different population. Newly edited or new nonignored public real toolkit sources are legitimate; their actual byte hashes are recorded. This file population and the marketplace normalized-body population must remain distinct.
- **Agents:** real public immediate `agents/*.md`, excluding `README.md`.
- **Commands:** real public immediate `commands/*.md`, excluding `README.md`. `commands/router/*.md` wrappers are separately listed/counted; `totalCommands` is their sum. Other recursive folders are not silently added. Website slash-command listings show the base population; the index labels base plus router totals explicitly.
- **Hooks:** distinct real public hook files selected by parsed `settings.json` event groups' `HOOK_NAME` assignments. The existing count convention also includes the wired `statusLine` script. `run-hook.js` is a dispatcher, not a lifecycle hook. Private/unwired hooks never enter the public inventory. Event/matcher identity is recorded once per file; a metadata description is not membership authority.
- **Repositories:** all reviewed `.gitmodules` entries, not every local clone, installed plugin, or unique remote URL. Section identity must match its path and each measured Git origin must match the credential-free public GitHub manifest identity. An explicit reviewed export may supply one entry's committed evidence from another existing canonical checkout (see below); native installed packages never qualify. No source refresh pulls, repairs remotes, mutates clones, or overwrites working edits.
- **Marketplace skills:** regular tracked `SKILL.md` **blobs at each checkout's selected HEAD commit**, after the shared public directory exclusions. Core-only vendor/imported/installed runtime-tree exclusions do not redefine a reviewed manifest repository's committed collection. Strip initial YAML frontmatter, collapse whitespace, lowercase; discard empty bodies; deduplicate SHA-256 body hashes within each repo and globally. Per-repo counts overlap: never sum them to obtain the global total. Dirty/untracked/generated installed content is never measured. A dirty checkout is recorded as `modified`, not erased or used as a filesystem source.
- **Display:** `marketplaceSkills` is exact; `marketplaceSkillsDisplayValue` floors to a hundred; `marketplaceSkillsDisplay` formats that lower bound in `en-US` with `+`. It is not an exact total, two-significant-digit rounding, or an upstream freshness guarantee.
- **Other existing fields:** rules/checklists are immediate public Markdown definitions; templates are represented top-level public template artifacts; `mcpServers` reflects the documented installed-server section, not a runtime tool probe. `skillDirectories` counts represented public top-level skill folders, not private/linked/empty runtime folders.

Marketplace blob ingestion is a **hash-only boundary**, not text publication or instruction execution. Fatal UTF-8 decoding, exact batch blob identity and byte framing, canonical checkout/origin/HEAD evidence, and complete source coverage remain required. Valid UTF-8 C0 control examples, including literal NUL in a Markdown code span, do not make a committed skill body ineligible: NUL remains in the normalized body and its SHA-256 input, without stripping, replacing, escaping, whitelisting or skipping the source. A nonempty normalized body qualifies for this population, not as a capability or semantic-quality assessment. Only derived hashes/metadata leave collection; raw marketplace instructions are never published or executed. NUL rejection in staged-public-safety and public-output privacy guards remains unchanged because those are separate text-publication boundaries.

## Explicit source refresh

When authorized, perform a single source write from an existing complete canonical checkout:

```bash
# Only if discovery/tiering inputs changed; this can update public settings.json.
node ~/.claude/scripts/generate-index.mjs --write

# Measure once, publish all explicitly selected consumers together.
node ~/.claude/scripts/generate-counts.mjs --write --as-of=YYYY-MM-DD \
  --travis-repo /path/to/travisjneuman \
  --portfolio-repo /path/to/tjn.portfolio \
  --denylist-url-file=1=/absolute/existing/franchises.json
```

### Explicit offline committed-source exports

If native Claude has replaced a marketplace directory with a packaged snapshot without `.git`, leave that runtime directory alone. Do not count package files or use `.gcs-sha`, clone/move/replace a cache, silently fetch another source, drop coverage, or reuse an old aggregate as fresh. The only alternative is an explicitly caller-reviewed export from an **existing canonical Git checkout** of the same registered source:

- `exportSnapshot(root, manifestEntry, asOf)` in `count-inventory.mjs` returns `{ definitionVersion, measuredAsOf, repo }`; it writes nothing. `root` is the existing toolkit root, and `manifestEntry` must exactly match its `.gitmodules` name/path/public GitHub URL. The helper calls the native `collectMarketplaces(root, [registered])` once: canonical checkout and origin guards, captured HEAD/tree, complete regular committed public `SKILL.md` selection and Git blob reads all remain in force. It accepts no input-provided shell commands.
- The parent executor may copy **only this reviewed collector module** to a nonrepository state folder on the source host and execute that helper for the actual export. Transfer its derived public JSON/hash metadata only, never a repo copy, raw skill bodies, credentials, SSH details or absolute source-host paths. Export/transfer are explicit parent operations, not work performed by the producer.
- Pass repeatable `--marketplace-snapshot-file=manifest-name=/absolute/existing/source-snapshot.json` to the producer or `update-counts.sh`. Duplicate or unregistered names, nonabsolute/missing/linked/nonregular files, files over 64 MiB, invalid UTF-8/JSON and unexpected object fields fail closed. No automatic fallback selects this flag. All other entries retain native Git collection and complete coverage guards.
- Import checks the current definition version, exact manifest name/relative path/URL/display name, valid observation date, `committed-HEAD-snapshot` mode, `clean`/`modified` source state, lowercase 40- or 64-hex Git revision/tree/blob IDs of consistent width, sorted distinct canonical public skill paths and SHA-256 body hashes (or null for empty normalized bodies). It reconstructs the ordered file records, verifies their deterministic `inputDigest` and per-repo unique count, then unions those nonnull hashes with every native source for **global** deduplication. It never sums per-repo counts.
- `measuredAsOf` is the actual source observation date supplied by the exporting parent, not an inferred commit/upstream date. It must not exceed publication `--as-of`. Same-day exports use that date; older reviewed exports retain their separate date, never get relabeled fresh. Imported rows retain `inputMode: committed-HEAD-snapshot`, `transport: reviewed-committed-snapshot-export`, original `measuredAsOf` and `snapshotDigest` (SHA-256 of the selected export file bytes). Aggregate input digest includes this transport/date evidence. Counts, website and portfolio JSON retain the same `snapshotExports` provenance; profile metric source text retains each export's name, observation date, transport and byte digest. Selected export bytes are reread before staging to detect changes; native sources still get their HEAD-change guards. Staging/promotion logic is unchanged.

**Trust boundary:** this is reviewed data transfer, not cryptographic proof of completeness or blob-to-body-hash binding. Metadata alone cannot independently reconstruct Git blobs, authenticate a claimed tree or prove that no eligible path was omitted. The parent must review the module and execute it against the approved existing clone with the actual observation date, then select that exact output. Arbitrary hand-authored metric JSON is not an authorized source even if internally consistent. No latest-upstream claim is made, and dirty/pinned sources remain identified and untouched.

### Offline privacy inputs (required before any staging)

The caller sources the existing private showcase environment outside the producer, then selects the reviewed canonical private static alias-registry counterpart. Do not print its configured URL, inspect/copy its private payload into public outputs, clear the configured URL list or substitute arbitrary metric sources/private APIs. `scripts/public-output-safety.mjs` performs only bounded local reads and local pattern matching; it never fetches.

- Required canonical pattern policy: `~/.claude/local/public-safety-patterns.txt`, retaining its extended-regex semantics via `grep -E`. Missing/unreadable/empty policy, invalid patterns and matcher failures block publication. Optional `--private-pattern-file=/absolute/existing/file` adds a policy; it never replaces the canonical policy. These repository-local private-project patterns apply to toolkit outputs and its staged-file gate, not to a different repository's intentional public owner biography/product names. Complete profile/portfolio outputs retain the shared literal/identity/alias gate. The owner explicitly confirms the existing public contact address is not private: only exact matches of that canonical address are exempt, never their surrounding line or any other match. Every pattern is retained/compiled and every returned match is inspected; neither patterns nor hits are printed.
- Literal union: the existing `~/.config/showcase/denylist.txt` when present, plus explicit `SHOWCASE_DENYLIST` when configured. All configured inputs must be readable regular UTF-8 files. Comments/blank lines are ignored; meaningful literal/name/alias terms are required overall, with no `--allow-no-denylist` escape hatch.
- JSON union: all existing comma-separated `SHOWCASE_DENYLIST_JSON_FILES` plus repeatable additive `--denylist-json-file=/absolute/existing/file`. Every file must supply meaningful name/alias terms; adding a file never satisfies/removes a configured URL slot.
- Every 1-based comma-separated `SHOWCASE_DENYLIST_JSON_URLS` position requires its own `--denylist-url-file=position=/absolute/existing/file`. Duplicate/unconfigured positions fail, and the selected basename must exactly match the configured URL's final filename. Filename equality is necessary, not proof of equivalence: the caller must review/select the approved canonical counterpart. Configured URLs are preserved in memory and never printed, fetched or rewritten. Unmapped URLs fail offline; there is no remote fallback.
- JSON/text safety reads are bounded to 2 MiB each; at most eight configured/additive JSON sources, including mapped URL slots, are accepted. JSON uses the profile guard's recursive `name`/`alias` field/array traversal and public-owner-name exclusions. Invalid JSON, UTF-8, traversal or empty alias registries fail closed.

#### Reviewed registry adapter (source version `unidentified-manager-v1`)

The optional private policy is `~/.config/showcase/reviewed-registry.json`, shared in schema with the generic showcase collector; each collector implements it locally without another-checkout dependencies. Only the publishing parent creates this file. Its exact five own keys are `schemaVersion: 1`, `urlSlot: 1`, `basename: "franchises.json"`, `sha256` (a lowercase 64-hex SHA-256 equal to the full artifact digest approved in the safety module), and `adapter: "unidentified-manager-v1"`. No source URL, private identities, aliases, credentials or additional keys belong in the policy. Reads are bounded to 4 KiB and require regular-file, fatal UTF-8 and valid JSON handling. Absent policy means ordinary complete extraction with **no omission**. A present unreadable, malformed or inconsistent policy, missing/mismatched configured URL slot 1 or selected basename, or changed full source-byte digest blocks publication pending renewed review. The digest is computed from the exact bounded source bytes subsequently parsed, before UTF-8/BOM handling or JSON re-encoding; neither filename nor record shape authenticates the artifact by itself. Changing the pin alone cannot approve a new artifact: this adapter version also binds the reviewed digest in source.

Only mapped configured URL slot 1's selected `franchises.json` may use the adapter. Explicit/additive JSON files (even the same path), other mapped slots, literal files and regex policy never receive it. In that pinned artifact, only a direct root `franchises` array record's own scalar `name` whose **raw** string equals `Unknown` case-insensitively is omitted. No trimming, normalization, substring matching or general stopwords select the exemption. The record must own all eight reviewed fields: meaningful string `id`, `slug` and `displayName` (trim-nonempty with a letter or digit; distinct from the usable-deny-term length floor), string `name`, empty array `managerAliases`, nonempty array `teamAliases` with every member a meaningful string, and nonempty string `primaryColor` and `secondaryColor`. Unsupported/changed shapes retain normal protection. Other properties still recurse normally, including display names, aliases, nested fields and unrelated root properties. An `Unknown` display name, alias, other name field or configured literal remains protected. Only the missing-manager scalar is omitted, never its record or source.

This is reviewed snapshot-specific identity extraction, not a public wording change or perpetual shape-only exception. Usable-term/nonempty gates and complete output scans remain unchanged. The safety module's changed bytes are already included in core input-file SHA-256 evidence/source module digests; private policy bytes and payload are never added to public provenance. This source revision alone does not refresh legacy root outputs or certify a successful authorized writer run.

Both read-only and write modes privacy-scan **every complete proposed output string**, including unchanged README prose, local counts, cross-repo facts/count imports, settings-derived hook matchers and provenance, before the first staging/directory write. Any nonexempt hit under the destination's applicable policy blocks the entire destination set; diagnostics may identify only the fixed public destination basename and one-based line/JavaScript code-unit column, never a pattern, private term, source URL or matching text.

Both `--option=value` and `--option value` are accepted for ordinary value options. Repeatable selections use the exact `--marketplace-snapshot-file=manifest-name=/absolute/existing/source-snapshot.json`, `--denylist-url-file=position=/absolute/existing/file` and `--denylist-json-file=/absolute/existing/file` forms. Omit either consumer argument for a deliberately local-only destination set. `--sync-consumers` is a compatibility flag, but requires at least one explicit destination. Environment variables do not silently enable destinations.

`--as-of` is optional (default current UTC date); it labels the measurement, not the commit date or latest upstream update. Each source revision is a selected **snapshot**, including deliberate dependency pins. Never infer that every host or upstream is fresh from the date.

The wrapper `bash scripts/update-counts.sh` defaults to `--write`; explicit `--check` prevents writing. Direct producer invocation defaults to read-only drift reporting. Both modes together, duplicate/unknown flags or snapshot names, invalid dates, missing consumers/markers, wrong identities, unreadable Git blobs, or any manifest entry lacking a valid native clone or explicitly selected reviewed committed export are visible errors. There is no partial coverage threshold, zero-count substitution, or old-count-as-fresh fallback. Tests/checks/builds/lints/sample executions require explicit owner authorization; these command descriptions are not permission to run them.

## Output contract (schemaVersion 2)

- `counts.json`: existing numeric fields plus `schemaVersion`, `definitionVersion`, `asOf`, numeric/string marketplace display fields, `inventory` lists (`skills`, `agents`, `commands`, `routerCommands`, hook file/events/matchers, rules/templates/checklists), and `provenance`.
- `provenance.core`: selected toolkit `revision`, `public-working-source` mode, clean/modified source state, deterministic input digest and public relative input-file SHA-256 evidence. If publication updates an owned numeric phrase inside a command source, evidence describes its planned final bytes; original bytes are retained in memory for pre-write change detection. Uncommitted public sources are explicitly identified as such; the HEAD revision alone does not describe them.
- `provenance.marketplace`: complete coverage, repo count, committed-snapshot mode, normalization, input digest, explicit snapshot freshness qualification and `snapshotExports` with each imported source's revision/tree/input digest/original observation date/transport/export-byte digest. This provenance is shared by local, website and portfolio outputs; profile source text carries imported names/dates/transport/export-byte digests. Earlier observations are preserved, not relabeled with the publication date.
- `website/src/lib/data/marketplace-counts.json`: matching schema/date/provenance/display and exact global total; compact manifest-only rows with name/path/URL/display name, exact per-source `skillCount`, revision/tree, clean/modified state, input mode/digest, `measuredAsOf` and `selectedFileCount` (full selected record-array length, not a unique-body count). Imported rows retain reviewed export transport and byte digest. An explicit uniform public projection omits every source's per-file arrays; complete path/blob/body-hash records remain in collection and reviewed input exports for normalization, global deduplication, digest calculation and final source checks. No selective private-term-based pruning occurs. Revision/tree/definition/module evidence and digests support reproduction when selected objects/exports remain available; digests alone do not prove completeness, binding or availability. Every complete compact toolkit output still passes the toolkit privacy gate. No absolute host paths, private runtime data, raw bodies, remote credentials, or status filenames are emitted.
- `plugin.json` and the producer's explicit current-document list: owned aggregate claims only, including the skills README and AI/custom-agent/community-plugin phrases. `CHANGELOG.md` and archives remain untouched. In every current Markdown consumer, History/Changelog/What's New, version and dated heading sections (including their nested headings) retain their original baselines; heading-like examples inside code fences do not define section boundaries. Current sections after history still update. The documentation index and ecosystem tables map explicit component labels to canonical fields, not row positions. MCP rows are labeled `Installed MCP entries (documented)` and count only the installed section of `docs/MCP-SERVERS.md`, never its optional-server catalog or runtime configuration. Marketplace rows mean manifest entries and nonempty normalized unique skill bodies with the floor-to-100 display. Total host/device/configured-project Git repositories are `Not measured`: parent plus manifest entries is a different population, not an installed-clone census. Owned folder-summary counts use the same canonical skill, directory, agent, base/router command, rule, hook and template fields; unrelated category breakdowns, illustrative sizes and script totals are not inferred. Marketplace guide updates target owned aggregate claims only, not upstream collection examples or external discovery-service counts.
- `.github/social-preview.html`: existing owned `data-count` numeric slots and snapshot-date comment are synchronized as source HTML only. Its external font import is removed in favor of system stacks. No image is rendered, and no currently configured social-upload/OG image is assumed to change.
- With `--travis-repo`: rewrite only numbers in `README.md` between exactly one ordered `<!-- claude-counts:start -->` / `<!-- claude-counts:end -->` pair. Exactly one numeric custom-skills, specialist-agents, commands, and marketplace-skills phrase is required. Preserve Travis's voice and all text outside that region. Update existing `showcase/local/tjn-claude.json` skills/agents/community/repos metrics from this same measurement, with string values, stable optional keys, public source/digest/revision/date provenance and truthful `round: exact` / `floor-100`. Keep status, copy, and unrelated metrics. Reviewed legacy labels map explicitly: `Skills` → `skills`, `Agents` → `agents`, `Community` / `Community skills` → `community`, and `Repos` → `repos`; publish canonical labels, never guessed array indices. Duplicate keys, duplicate legacy/new authorities and conflicting recognized label/key pairs fail closed. The profile schema must permit those optional keys and `floor-100`.
- With `--portfolio-repo`: write `src/lib/data/claude-counts.generated.json`, containing public core counts, marketplace fields, date and provenance; no TypeScript prose rewriting or full inventory duplication. Portfolio source imports it. Do not change `portfolio:false` or create a generic card.

All planned content is prepared in memory and **all destinations and complete output strings preflight before any write**. All changed files and byte-exact original backups are then staged before the first promotion in unique adjacent `.claude-counts-stage-<uuid>/` directories. Each stage writes a self-ignoring `.gitignore` before any artifact bytes, including in cross-repo consumers; root policy also ignores these directories. Existing files promote by atomic rename; new files use exclusive hard-link creation (fail closed where unsupported). File permissions and original bytes are preserved. Source/output changes, replaced inodes, symlinks, modes or timestamps abort publication at the observed boundaries. Rollback only restores/removes promotions whose current inode, metadata and bytes still belong to this run; later edits are left intact. Incomplete rollback retains ignored original-byte copies for manual recovery and reports failure. Cleanup is nonrecursive and never removes unexpected contents. This is not crash-atomic or a filesystem compare-and-swap transaction across repositories: a last-check/rename race cannot be eliminated for uncooperative editors, so concurrent editing/publication remains unsupported and the publishing owner must review the actual final diff. No output is reported successful when promotion, final ownership checks or staging cleanup fail. Success reports measurement population/date/counts and changed paths. Error exits nonzero, and successful read-only drift reporting exits nonzero if planned outputs differ.

## Website and hook behavior

Local and hosted builds consume the same committed JSON snapshot. Public resource collectors read only those identity lists, rejecting missing/linked source files rather than discovering private or synced content. Marketplace membership, URLs and exact/display totals never come from local raw-file counts. Legacy snapshot schemas fail visibly until the explicit source write is complete. Existing components/styles are preserved.

Pre-commit retains marketplace/gitlink, public-safety pattern, credential and ignored-runtime safety gates. The shell entrypoint invokes `scripts/hooks/staged-public-safety.mjs`, which uses NUL-delimited index identities and reads final staged `cat-file blob` bodies, never working-tree bodies or added diff lines. Private-pattern policy loading/compilation/matching errors block rather than being swallowed. Whole staged text (including settings/source files and removed-context leftovers) is scanned; recognized encoded binary assets are not image/pixel-scanned. Credential exceptions require a complete quoted value: whole environment references are allowed on all paths because they contain no credential payload; reviewed synthetic/truncated instructional literals are allowed only by the hook's exact public example path-to-literal map, never globally in settings, scripts or arbitrary Markdown/JSON/code fences. Prior publication alone does not make a credential safe, and the private-pattern gate still scans every complete example body before any literal exception. No pattern, matching line, private filename/value or Git stderr is printed. Gitlinks, staged marketplace clones, private/runtime paths, ignored files and count-stage remnants remain blocked. It does **not** run generation, budget/structure tests, index checks, hidden consumer writes, or automatic staging. Commit-time regeneration previously swallowed errors and changed outputs after safety review; explicit refresh removes that risk without bypassing any guard. Pulling sources also does not refresh public numbers. Review generator output and the actual diff, then let the normal publishing owner stage/commit/push. No generators run implicitly during count publication.

## Separate media operation

Count-free website OG art requires no count refresh. There is no implicit image/card/showcase generation or asset delivery. Prefer a separate explicitly approved DESK media operation after reviewing canonical counts.

The optional `--sync-images` compatibility route requires **all** of `--write`, an explicit `--renderer-path` to the reviewed `.mjs` renderer, and `--image-output-dir` to the existing dated `<slug>-<yyyy-mm-dd>` job folder supplied by `desk-run` as `TJN_MEDIA_WORK`, on the approved Windows media host. `scripts/media-routing.mjs` requires the owner-reviewed private `~/.config/showcase/media-production.json`: exactly `schemaVersion: 1`, uppercase `hostname` and canonical absolute `jobsRoot`, with its complete raw bytes pinned by the reviewed module's SHA-256. Changing the file requires renewed routing review; a valid-looking replacement cannot authorize another host/root. It uses actual `os.hostname()` and Windows platform identity, not a spoofable hostname environment variable. Hostname/job-root values never appear in public source, errors or count provenance; missing, linked, oversized, malformed or wrong-host policy fails closed. Linked or repository output folders are rejected. Its renderer contract is `--write --counts-file=<counts.json> --output-dir=<work folder>`; it must write only finished assets there. No portfolio destination is passed to it. Rendering or final delivery/publishing remains a separate approved operation, with source logos copy-only. A renderer failure rolls back the count writes and exits nonzero; incomplete work-folder media is not a published artifact. Do not use a legacy renderer that ignores this output contract.
